Дата: 28 октября 2026 года. Задача: упорядочить существующий проект без изменения игровых правил и дизайна. - JSON не изменены. Формулы, диапазоны уровней, порядок суммирования/лимитов, единицы attack_spead, выбранные варианты и формат localStorage сохранены.
- Не изменены размеры расклада 4×3, drag-and-drop, случайные цели слотов, eligibility способностей и правила назначения unique-эффектов.
- Разделение basic-расчёта и визуальных unique/neutral-связей сохранено. Не добавлены обратные стрелки или новые игровые эффекты.
- Публичные props компонентов не менялись; экспорт повторяющегося форматтера добавлен в существующий компонентный файл.
- Inline-стили для координат, редкости, тематических цветов и SVG оставлены: это реальные динамические значения.
- Таймеры и DOM-подписки имеют cleanup; асинхронные переключения противников защищены от устаревших запросов. Универсальный хук подписок не добавлялся: различия поведения важнее небольшого повтора.
- Не удалялись изображения, standalone-режим EnemiesPage, тестируемые утилиты и публичные fallback-компоненты только из-за того, что основная сцена использует другой путь.

## Оставшиеся ограничения и рекомендации — не выполненные изменения

1. **Нет browser E2E / визуальных регрессий.** После восстановления Browser host проверить все четыре страницы, широкое/узкое окно, скрытые меню, число и цвет связей, открытие/закрытие категорий, Escape, hover, варианты, drag/drop и reload. Не менять анимации дальше без такой проверки.
2. **Achievements.json — файл размером 0 байт.** Он не импортируется приложением, поэтому сборка не падает. Перед созданием раздела достижений нужно определить реальную схему и заполнить файл. В этом аудите данные не выдумывались.
3. **Большой единый JS-чанк.** Игровые JSON и все страницы входят в сборку. Разделение возможно после измерений загрузки; наивный lazy mount нарушит сохранение состояния и выходные анимации постоянно смонтированных меню. Лимит предупреждения не повышался, чтобы скрыть проблему.
4. **Unique-механики описательные.** Условное лечение, превышение уровней и прочие unique-эффекты не симулируются. ID 11 и 16 в arcanaConnectionViews — явные соответствия текстам текущих карт. При изменении данных потребуется проверить этот адаптер; знак bonus_value сам по себе недостаточен для любой unique-механики.
5. **JSON типизирован не полноценной runtime-схемой.** Данные локальные, их проверяют TypeScript и тесты, а сохранения валидируются отдельно. Перед внешним импортом данных потребуется отдельная валидация. Стороннюю schema-библиотеку без такой задачи не добавляли.
6. **Редьюсер skillVariant проверяет целочисленность/нижнюю границу, а восстановление — реальную способность и верхнюю границу.** Текущий UI генерирует корректные варианты через nextSkillVariant. Усиление API-валидации можно сделать отдельной задачей с контрактными тестами; в данном рефакторинге публичное поведение не менялось.
7. **Часть generic-описаний врагов остаётся строкой JSON.** Форматирование чисел героя/Арканов и параметров покрыто formatNumber, но текстовые числа внутри произвольной строки врага не преобразуются общей функцией автоматически. Изменение такого вывода требует отдельного задания.
8. **Ресурсы стартового шаблона в src/assets сохранены.** Прямые импорты не найдены, но удаление графики не необходимо для текущего результата. Основной объём изображений намеренно не чистился.
9. **Общие мобильные overrides scene-menu/панелей остаются в transitions.css.** Это координация нескольких страниц, а не случайный дубль. Похожие стили селекторов не сведены в один новый компонент: различаются яркость, промежутки и мобильные размеры. Различия сохранены ради запрета менять внешний вид.
10. **Полный TypeScript strict не включён.** Текущие конфигурации проверяют неиспользуемые переменные/параметры и проваливание ветвей switch, но не включают strictNullChecks. Отдельный переход на strict потребует проверки nullable-границ и тестов. Успешный текущий build не следует называть проверкой strict-режима.
