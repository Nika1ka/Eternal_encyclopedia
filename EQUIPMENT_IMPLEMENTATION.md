# Страница «Экипировка»

> Актуальная архитектура, сохранения, стили и команды проверки описаны в [PROJECT_DOCUMENTATION.md](PROJECT_DOCUMENTATION.md). Этот файл сохраняет дополнительные заметки по разделу; старые списки проверок и этапы реализации не являются текущим отчётом аудита. См. [CODE_REVIEW_REPORT.md](CODE_REVIEW_REPORT.md).

Маршрут `#/equipment` подключён к верхней навигации. `HeroesPage` служит одной общей сценой для режимов `heroes` и `equipment`: герой, способности, уровни, панель характеристик и эффекты не дублируются. Для каждого героя хранится своя сборка из трёх слотов. Переходы между разделами сохраняют состояние.

## Реализовано

- Каталог всех 50 предметов в пяти колонках редкости, прокрутка, SVG-связи и подсветка соседей. Связи соединяют последовательные позиции только внутри одного `item_group` (32 связи, 18 групп). Чёрный фон имеет alpha 0.7, каталог занимает всю высоту.
- Нажатие открывает карточку осмотра, не экипируя предмет. Карточка содержит изображение, название, редкость, уровни 1–3, цену и ресурсы, атрибуты, отдельные блоки способностей, исходную историю предмета.
- Уровень предпросмотра независим от сборки. В карточке экипированного предмета звёзды меняют уровень реального экземпляра и синхронизируются со звёздами слота.
- Native Drag & Drop копирует предмет в любой из трёх слотов. Каталог сохраняет предмет. Недопустимые и отменённые переносы не изменяют сборку; занятый слот можно заменить, новый экземпляр получает первый уровень.
- Кнопки установки в слот в карточке предоставляют альтернативу перетаскиванию для клавиатуры и сенсорного ввода. Из карточки слота можно снять предмет. Карточка закрывается крестиком, Escape, нажатием снаружи и при смене маршрута; возвращает фокус исходному элементу.
- Изменения сборки обновляют здоровье, щит, атрибуты и единый список `hero-effects`. Эффекты других источников сохраняются. Пустой список эффектов не создаёт блок.
- Дополнительные бонусы начисляются за каждый уровень после первого. Атрибуты складываются непосредственно, процентные величины — в процентных пунктах. Знак `Spell_cooldown` сохраняется в карточке и панели героя.
- В описаниях показаны итоговые значения и накопленные прибавки в скобках. Полезные изменения зелёные, вредные — красные. Для параметров штрафов и времени ожидания направление полезности задано явно в метаданных.
- Каталог лениво загружает изображения; предусмотрен fallback повреждённого изображения. Пять колонок и SVG масштабируются совместно. На узких экранах каталог, сцена и информация размещаются вертикально.

## Проверки

- `node --test tests/heroes.test.ts tests/equipment.test.ts`: 28 тестов пройдено, включая 15 существующих проверок героев.
- `npm.cmd run lint`: без ошибок.
- `npm.cmd run build`: TypeScript и production-сборка Vite успешны.
- Проверены пути всех изображений предметов, способностей, ресурсов и иконок характеристик; все подстановки описаний для уровней 1–3 заполнены.
- «Проклятый клинок» уровня 3 соответствует числам референса: атрибуты `60, -60, 100`, параметры способностей `[100, 70, 25, 80, 200, 90]`.
- Автоматические тесты проверяют расчёты и состояние, но не заменяют браузерную проверку открытия карточек и настоящего перетаскивания. В доступном окружении список подключённых браузеров пуст; чтение окна Chrome с локальной страницей завершилось ошибкой `window is minimized`. Визуальное соответствие референсам и указанные размеры экрана не объявляются проверенными.

## Ограничения и дальнейшая интеграция

- По согласованному правилу уникальные способности предметов отображаются как эффекты с параметрами текущего уровня. Условные боевые механики из свободного текста не прибавляются к численным характеристикам.
- Одновременно разрешён один предмет из каждого `item_group`. Установка в другой слот блокируется в карточке, при переносе и в reducer; замена внутри исходного слота разрешена.
- `spell_damage` и `spell_cooldown` применяются к полям `damage` и `cooldown` способности после бонусов уровня: значение умножается на `1 + атрибут / 100`. Открытая карточка обновляется при изменении экипировки. Произвольные числовые параметры описания и дополнительных эффектов не масштабируются, поскольку не имеют структурированного признака урона.
- Постоянного сохранения сборок в проекте пока нет. Сериализуемый `BuildState` подготовлен для будущего подключения сохранения; сейчас сборка живёт до перезагрузки страницы и сохраняется между маршрутами.
- Цена не меняется от выбранного уровня, поскольку правила стоимости улучшения отсутствуют.
- Известные имена ресурсов обработаны без изменения файлов: `Midnight_Prism.png.png` и `Gols.png`.
- Для завершения визуальной приёмки нужны доступный браузер и проверка desktop-размеров 1648×928, 1920×1080, 1600×900, 1366×768, узкого экрана, открытия/закрытия карточек и реального переноса мышью.
