# Страница «Герои»

> Актуальная архитектура, сохранения, стили и команды проверки описаны в [PROJECT_DOCUMENTATION.md](PROJECT_DOCUMENTATION.md). Этот файл сохраняет дополнительные заметки по разделу; старые списки проверок и этапы реализации не являются текущим отчётом аудита. См. [CODE_REVIEW_REPORT.md](CODE_REVIEW_REPORT.md).

Запуск: `npm run dev`. Страница доступна по `#/heroes`; остальные три раздела — заглушки. Навигация на hash URL работает на статическом хостинге без серверных правил перенаправления и дополнительных библиотек. Пути изображений учитывают Vite `BASE_URL`; для GitHub Pages используйте `npm run build -- --base=/Game_encyclopedia/` (или своё имя репозитория).

## Реализовано

- Семь героев из `Characters.json`, оригинальные портреты, модели и индивидуальные фоны.
- Уровни 1–5 с отдельным состоянием каждого героя в пределах открытой страницы; начальный уровень — 1. При переходе между разделами выбранный герой и уровни сохраняются. Цвет звёзд по уровню: серый, зелёный, синий, фиолетовый, красный. Все звёзды имеют один оттенок; незаполненные приглушены.
- Характеристики из `base_attributes`, включая исходное поле `attack_spead`, умноженное на 0.01. Щит слева, здоровье справа. Для пяти оговорённых отсутствующих вторичных характеристик — 0%.
- Пассивная способность находится в слоте 0; слоты 1–4 содержат способности 0–3 из JSON. Стрелки у трёх активных способностей циклически переключают базовую версию и два `additional_effects` в обе стороны. Иконка соответствует выбранному варианту. В новом макете шапка сохраняет базовое название способности, а название и описание выбранного эффекта показаны в отдельном нижнем блоке. При смене героя варианты сбрасываются; при смене уровня сохраняются.
- Карточка способности содержит иконку, интерактивные звёзды общего уровня героя, перезарядку и ненулевой радиус с оригинальными значками, базовое описание, урон и длительность. Значения и проценты выделены жирным `#8A9BC3`, накопленные бонусы — жирным `#59D453` в скобках после итогового значения. Базовый текст и текст эффекта обрабатываются раздельно, без HTML-вставок.
- Звёзды карточки и правой панели используют общий `LevelStars`. Интерактивная карточка имеет роль немодального диалога; стрелка вниз с кнопки способности переводит фокус на звёзды, Escape возвращает его к кнопке. Наведение и фокус внутри карточки удерживают её открытой.
- Фоны, модели и иконки плавно сменяются за 340 мс после загрузки нового изображения. Старое изображение остаётся на экране до загрузки нового. Учитывается `prefers-reduced-motion`. Пустой `hero-effects` не рендерится и не занимает места.
- `upgrade_per_level_bonuses` применяется накопительно ко всем пяти способностям: на уровне 1 бонусов нет, на уровнях 2–5 применяются первые 1–4 записи. Пятый бонус недоступен. Теги `valueN` изменяют `skill_values[N - 1]`, `damage`, `range`, `duration` — соответствующие параметры. Бонусы `cooldown` вычитаются, остальные прибавляются с учётом знака числа. Подсказки и строки параметров обновляются, включая уже открытые. Исходные данные и значения дополнительных эффектов не изменяются.
- Рамки находятся позади иконок; стрелки — отдельные кнопки, положение которых задаётся в `heroes.css`. Верхняя навигация: 50×50px, активная вкладка 70×70px, промежуток 45px.
- Размеры текста используют `rem`, размеры основных блоков ограничены в `rem`, сохраняя адаптивное уменьшение под доступную область. Масштаб браузера больше не компенсируется исключительно единицами `cqw`.
- Подсказки доступны при наведении, фокусе и нажатии; повторное нажатие, Escape, нажатие вне подсказки или смена героя закрывают их. Размеры и положение ограничены экраном.
- Три пустых слота экипировки; предусмотрены типы и компоненты для предметов, звёзд предметов и активных эффектов.
- Оригинальные `skill_arc.png`, `skill_frame.png`, `change_skill_button.png`, `frame delim.png`, звёзды и иконки характеристик.
- Отдельная компоновка для узких экранов, прокрутка истории и списка портретов, состояния фокуса, `prefers-reduced-motion`.

## Особенности исходных данных

- Числа на референсах отличаются от JSON. Отображаются значения JSON, например Фея: щит 15, здоровье 5; Призрак: щит 12, здоровье 3.
- Нет назначенных героям предметов, их уровней и экземпляров активных эффектов. Эти блоки не заполняются вымышленными данными. `Equipment.json` содержит каталог предметов, а не экипированную сборку.
- Нет правил роста базовых характеристик героя: уровень меняет способности, но не `base_attributes`.
- В текущем JSON второй бонус «Парирования» (`Demon_dash.png`) ссылается на `value3`, но `skill_values` содержит только два числа и в описании нет `${value3}`. Этот бонус невозможно корректно применить без исправления ссылки в исходных данных; фиктивное базовое значение не создаётся.
- Имена в JSON английские; подписи интерфейса локализованы в `characterAssets.ts` без изменения JSON. Фоны сопоставлены по именам файлов, включая `Wizard_backgound.png`, `Ghost_background.png.png`, `Summoner_background.png.png`.
- Первой выбрана Фея для соответствия основному референсу. Пассивная способность определяется по суффиксу `_passive.png` и выводится первой без изменения исходного JSON.

## Проверки

- `npm run build` — TypeScript и production build.
- `npm run lint` — ESLint.
- `node --test tests/heroes.test.ts` — проверка данных, шаблонов описаний, числового форматирования и наличия изображений (Node.js 24).

В Windows PowerShell при запрете запуска `npm.ps1` используйте `npm.cmd`.

Визуальная проверка и проверка взаимодействий в браузере не выполнены: Computer Use остановился, поскольку не смог надёжно определить URL окна Chrome. Следует проверить Фею и Призрака при 1920×1080, 1600×900, 1366×768 и на узком экране, переключение всех героев, уровни, навигацию, подсказки, консоль браузера и отсутствие горизонтального переполнения.
