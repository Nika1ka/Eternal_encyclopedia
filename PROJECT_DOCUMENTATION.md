# Техническая документация Game Encyclopedia

Актуализировано по исходникам и проверкам 28 октября 2026 года. Результаты аудита и ограничения проверки — в [CODE_REVIEW_REPORT.md](CODE_REVIEW_REPORT.md). Правила изменения проекта — в [AGENTS.md](AGENTS.md).

## Назначение и стек

Локальная интерактивная энциклопедия и конструктор сборок героя: герои, экипировка, Таро, противники и локации. Приложение не симулирует бой и не имеет серверного API, авторизации или базы данных. Игровые данные поставляются в JSON, изображения — в `public/assets`, сборки сохраняются в браузере.

Стек: TypeScript, React 19, React DOM, Vite 8 с `@vitejs/plugin-react`, обычный CSS. Проверки: TypeScript с noUnusedLocals/noUnusedParameters и noFallthroughCasesInSwitch, ESLint с React Hooks и Fast Refresh, встроенный `node:test`, SSR через Vite и React DOM Server. Полный режим TypeScript `strict` сейчас не включён. Точные разрешённые версии находятся в `package.json`, установленные — в `package-lock.json`. Новые зависимости при аудите не добавлялись.

Проверенная среда: Windows PowerShell, Node.js 24.22.1. Тесты `.ts` выполняются средствами Node, поэтому требуется версия Node с поддержкой удаления TypeScript-типов. Не заменять их запуск обычным старым Node без такой поддержки.

```powershell
npm.cmd ci                 # установка по lock-файлу
npm.cmd run dev            # адрес и порт сообщает Vite
npm.cmd run lint
npm.cmd test               # тесты логики и файлов ресурсов
npm.cmd run test:render    # SSR, не браузерный E2E-тест
npm.cmd run build          # tsc -b + production Vite build
npm.cmd run preview       # просмотр собранного dist
```

В других оболочках можно использовать `npm`. В PowerShell `npm.cmd` позволяет избежать запрета выполнения `npm.ps1`. Vite и TypeScript записывают кеш в `node_modules`; ограничения среды агента иногда требуют разрешения на такой запуск. `dist` — результат сборки, вручную его не редактируют.

## Публикация на GitHub Pages

Workflow `.github/workflows/deploy.yml` запускается при push в основную ветку `master` или вручную через Actions. Node.js 24 устанавливает зависимости через `npm ci`, затем `npm run build` создаёт `dist`; только содержимое `dist` передаётся в GitHub Pages.

В репозитории GitHub откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. После загрузки изменений в `master` дождитесь успешного выполнения workflow **Deploy to GitHub Pages**. Адрес сайта: `https://nika1ka.github.io/Eternal_encyclopedia/`.

`base: '/Eternal_encyclopedia/'` в `vite.config.ts` соответствует имени репозитория. Пути изображений используют `import.meta.env.BASE_URL`, а favicon в исходном `index.html` — `%BASE_URL%`. Vite подставляет базовый путь при сборке и заменяет `/src/main.tsx` ссылкой на собранный JavaScript. Если браузер запрашивает буквальный `%BASE_URL%` или `main.tsx`, опубликованы исходники вместо сборки. Публикация корня ветки через **Deploy from a branch** не выполняет сборку Vite.

Локальная проверка: `npm.cmd run build`, затем `npm.cmd run preview` и открытие `/Eternal_encyclopedia/` по адресу сервера. Навигация использует hash, отдельный серверный fallback для страниц не нужен.

`dist` и `node_modules` остаются в `.gitignore`: workflow создаёт сборку самостоятельно. Также исключены `.env` и `.env.*` (кроме шаблона `.env.example`), кеш TypeScript и `coverage`. Пустой файл `gitignore` без начальной точки удалён: Git не использует его как файл правил. `package-lock.json` должен оставаться в репозитории для `npm ci`.

## Вход, навигация и состояние

`index.html` → `src/main.tsx` → `App`. `App` подписывается на `hashchange` через `useSyncExternalStore`; отписка возвращается из `subscribe`. Стороннего роутера нет.

| Hash | Режим общей сцены |
|---|---|
| `#/heroes` | Герои |
| `#/equipment` | Экипировка |
| `#/upgrades` | Таро |
| `#/enemies` | Противники |

Список ссылок и иконок — `utils/navigation.ts`. Неизвестный путь показывает заглушку, общая сцена сохраняется скрытой. `HeroesPage` — владелец `useReducer` сборки, общего фона, навигации и расчётных характеристик. Название историческое: компонент обслуживает все четыре интерфейса.

`BuildState` (`store/buildStore.ts`) содержит:

| Поле | Назначение |
|---|---|
| `selectedHeroId` | Выбранный герой |
| `heroLevels[heroId]` | Уровень 1–5 |
| `equipmentByHero[heroId]` | Три слота `{ itemId, level }` либо `null` |
| `arcanaByHero[heroId]` | Двенадцать слотов Арканов |
| `variantsByHero[heroId][skill_image]` | Выбранный вариант способности, 0 — базовый |

Сериализация: ключ `eternal-battle-build-v1`, объект `{ version: 1, build }`. `restoreBuild` проверяет известных героев, предметы, группы, уровни, варианты и назначения способностей. Повреждённые либо неподходящие сохранения безопасно восстанавливаются с начальными значениями. Сохранение может быть недоступно при запрете localStorage; приложение продолжает работать в памяти. Старые сохранения без вариантов получают пустые словари. Старый `randomTargetArcanaId` мигрирует в слот.

Временные состояния не сериализуются: выбранная категория/карта, перетаскивание, предпросмотр, всплывающие окна, анимации. Локация/противник сохраняются при переходах внутри смонтированной сцены, но не входят в localStorage сборки.

## Игровые механики и неизменяемые правила

### Герой, экипировка, способности

Строки `hero-stats`, здоровье и щит героя показывают десятые. В `hero-tooltip` героя урон способности, перезарядка и радиус (включая разницу) показывают десятые; длительность, описание и дополнительные эффекты — сотые. Сравнение способностей в Таро, противники и остальные места сохраняют сотые. Округление вниз применяется только при выводе; расчёты сохраняют полную точность.

Герой имеет ручной уровень 1–5. «Умеренность» даёт подтверждённой способности +1 уровень, максимум 6. `skillAtLevel` применяет до пяти улучшений из JSON; базовые данные не мутируют. Положительное улучшение cooldown на уровне вычитается. Процентные модификаторы применяются после улучшений уровня. Индекс варианта выбирает дополнительный эффект и картинку; не является новым уровнем героя. Подсказки и сравнение показывают итоговый уровень, звёзды продолжают менять ручной уровень героя.

Три слота экипировки, ручной уровень предмета 1–3. «Колесо Фортуны» повышает итоговый уровень экипированных предметов, включая уровни выше 3: повторяются заданные в JSON приращения атрибутов и значений эффектов. Каталог показывает исходные уровни, описание экипированного предмета и его эффекты — итоговые. Нельзя иметь два предмета одной `item_group` в разных слотах; заменять предмет в том же слоте можно. Просмотр уровня предмета в каталоге не экипирует его. Реальный drop из занятого слота вне слотов снимает предмет; отмена drag не снимает.

Порядок атрибутов задаёт `calculateHeroBuild` (подробнее ниже); `limitHeroAttributes` применяется после всех эффектов. Лимиты: здоровье минимум 3; защита, магическое сопротивление и уклонение максимум 85; отображаемая скорость атаки минимум 0.5; урон минимум 10; шанс и величина крита минимум 0; cooldown минимум −75%; скорость перемещения минимум 50. Исходное поле `attack_spead` у героя хранит сотые, множитель отображения 0.01. У противников скорость атаки хранится напрямую.

Округление только для отображения: `1.7592 → 1.75`, `1.5 → 1.5`, `−5.7375 → −5.74`. Внутренние расчёты сохраняют точность. Разбор описаний подсвечивает числа; положительный/отрицательный цвет изменения зависит также от того, полезно ли снижение параметра.

### Таро

Расклад — 12 слотов, четыре столбца и три строки. Одна карта не может повторяться. Перенос установленной карты сохраняет её уровень и назначение; занятые ячейки при переносе меняются местами. Новая карта устанавливается только в пустую ячейку с уровнем 1. Ручные уровни 1–15, итоговые с бонусами — не выше 20. Снятие вне ячеек происходит только при настоящем drop, не при Escape или dragend.

Соседи — исключительно сверху, снизу, слева, справа. Строки не замыкаются. Basic-влияния соседей суммируются в «Временное усиление». `attributes_bonus` и `abilities_bonus` умножаются на `1 + amplification / 100`. `arcanas_bonus` не усиливается соседями, что исключает рекурсивное усиление.

`Affects_one_random_arcana` привязывает цель к соседнему **слоту**, в том числе пустому. Удаление карты из этого слота не меняет выбранную цель. При перемещении источника цель сохраняется, если по-прежнему соседняя; иначе выбирается новая при commit. Случайность не запускается в рендере или предпросмотре.

`Affects_one_selected_ability` требует назначения конкретной способности. Для basic-бонуса у неё должно существовать соответствующее конечное ненулевое значение; нельзя назначать бонус урона способности без damage. Проверка используется интерфейсом, редьюсером, восстановлением и калькулятором. Поддерживаемые unique-механики описаны ниже; остальные остаются описаниями, без симуляции боя.

### Уникальные эффекты и пассивные способности (31 октября 2026)

`calculateHeroBuild` используется на страницах героя, снаряжения и Таро, включая предпросмотр назначения способности. Он возвращает атрибуты, модификаторы способностей, эффекты экипировки и Арканов. Сохранение содержит только ручные уровни; бонусы пересчитываются после каждого изменения и полностью исчезают при снятии источника.

- «Влюблённые» повышают уровни ортогональных соседей, «Суд» — сохранённого соседнего слота, «Император» — одного сохранённого слота в раскладе, кроме собственного. Пустой слот допустим; повышение уровня источника не меняет цель. Цель выбирается при commit, при восстановлении старого сохранения без цели используется первый допустимый слот.
- Бонус уровней округляется вниз. Карты 11, 16, 37 не получают уровни от других карт. «Колесница» получает уровни от других Арканов, добавляет собственные +1 себе и +1 обычным картам независимо от своего уровня. Это исключает циклы. Итог любого Аркана ограничен 20; обычные бонусы рассчитываются по итоговому уровню. В раскладе и описании показан итог, кнопки меняют ручной уровень.
- «Сила» добавляет физическое и магическое сопротивление от итогового здоровья. «Маг» даёт плоский урон атаки и столько же процентных пунктов урона заклинаний за сумму итоговых уровней занятых соседних ячеек.
- «Колесница» процентом изменяет итоговые атрибуты. Сначала определяется показанное здоровье/щит, затем зависимые от них сопротивления. Ограничения применяются в конце; здоровье для зависимых эффектов учитывает минимум 3.
- «Некротические клыки» уменьшают запас здоровья и добавляют плоский вампиризм (показан отдельной характеристикой). «Демоническая натура» добавляет сопротивления за пустые слоты и урон атаки за занятые. «Призрачная оболочка» добавляет магическое сопротивление от показанного щита; убийства и накопление щита не симулируются.
- Эффект `Blood_River` экипированного предмета группы 0 добавляет плоский вампиризм из первого `skill_values`, рассчитанного по итоговому уровню предмета. Он суммируется с вампиризмом Некроманта; «Колесница» изменяет общую сумму своим процентом. После снятия предмета бонус исчезает. Подпись basic-бонуса случайной соседней цели в описании Аркана — «Бонусы одного из Аркан»; бонус всем соседям сохраняет прежнюю подпись.
- «Благословление фей» умножает величины бонусов к атрибутам и способностям. Количество уровней от «Умеренности», «Колеса Фортуны» и карт повышения уровня не усиливается. Для исключения саморекурсии значения пассивки Феи берутся после обычных бонусов, до её собственного усиления; эти же значения передаются в подсказку через `skillValueOverrides`.

Порядок: итоговые уровни карт → усиление соседей → бонусы Арканов с эффективностью Феи → экипировка с бонусным уровнем → пассивные способности → процент «Колесницы» и зависимые сопротивления → ограничения. Параметры способностей сначала получают улучшения уровня, затем процентные модификаторы. Восстановление выбранных способностей учитывает бонусный уровень «Умеренности».

### Визуальные связи Арканов

Расчёт игрового усиления и представление связей различаются намеренно:

- `arcanaInteractions` возвращает реальные basic-влияния для калькулятора.
- `arcanaConnectionViews` добавляет нейтральные направления и отображение известных unique-связей, не меняя характеристики.
- Визуализируется только исходящее влияние активной карты на её соседей: зелёное — усиление, красное — ослабление, серый пунктир — отсутствие эффекта, в том числе пустая целевая ячейка. В центре четыре направления, у края три, в углу два.
- Приоритет: drag над допустимой ячейкой → выбранная установленная карта → hover/focus. Выбор снимается через «К герою» или Escape. Обратные влияния показываются при выборе соседней карты.
- Unique-Аркан 11 («Влюблённые») визуально усиливает допустимых занятых соседей, 16 («Суд») — сохранённую случайную соседнюю цель. Защищённые от повышения уровня карты показывают нейтральную связь. Глобальная цель «Императора» указана в его описании; дуги соседства не используются для дальних ячеек. «Маг» вычисляет урон героя от соседей, а не усиливает их.
- Предпросмотр использует `reduceArcana` над копией состояния; не сохраняет сборку, не применяет бонусы и не угадывает случайную цель.
- SVG не принимает события, размещает линии в промежутках и измеряет реальные ячейки после монтирования. `ResizeObserver` отключается при размонтировании; одинаковая геометрия не вызывает обновление состояния.

### Противники

Эффекты локаций используют ту же карточку `EnemySkillTooltipCard` внутри `hero-tooltip`, что и способности противников: иконка, заголовок, описание с выделением чисел, без выбора уровня. Наведение, фокус, закрепление кликом и закрытие обслуживает общий `HeroTooltipScope`.

Правая колонка `enemyStatColumns`: скорость передвижения, вампиризм (`attack_lifesteal`), сопротивление замедлению (`slow_effectiveness`), эффектам (`effect_resistance`) и оглушению (`stun_resistance`). Урон заклинаний, снижение перезарядки и урон по постройкам не отображаются. Тип `EnemyAttributes` дополняет базовые атрибуты полями противников; значения берутся из JSON. Вампиризм — обычное число без `%`, сопротивления — проценты. Нули отображаются, отсутствующие значения обозначаются `-`. Дробные значения форматируются общей функцией `formatNumber`. Пять строк правой колонки центрируются по высоте относительно шести строк левой. Для героев набор характеристик не меняется.

Локации берутся из `Locations.json`. В каждой сначала просматриваются обычные враги, затем боссы. `Bosses.json` и `Enemies.json` используют одинаковую нумерацию локаций 0–7, без сдвига при загрузке. У боссов собственные ID: адаптер даёт боссу ID `−(sourceId + 1)`, чтобы избежать пересечения с ID обычных врагов. JSON не переписывается. Режимы описания врага/локации разделяют общий фон и панель. Изображения загружаются до перехода, устаревшие асинхронные запросы отбрасываются.

## Данные и ресурсы

| Файл `src/data/` | Корень / количество | Основные поля и потребители |
|---|---|---|
| `Characters.json` | `heroes`, 7 | id, name, icon_name, model_name, game_description[], base_attributes, skills; HeroesPage и навыки |
| `Equipment.json` | `items`, 50 | id, name, file_name, rarity, item_group, position_in_shop[], craft_price, attributes_list, item_abilities[], skill_values[], upgrade_bonuses; каталог и калькулятор |
| `Arcana_cards.json` | `arcanaCards`, 42 | id, name, file_name, card_type, major_arcana_number?, category, game_description, additional_tags[], три необязательные секции бонусов; Таро |

| `Enemies.json` | `enemies`, 76 | id, name, model_name, enemy_location_id, game_description, base_attributes, skills; карусель |

| `Achievements.json` | Пустой файл | Не импортируется; пока не является валидным JSON и не имеет реализованного интерфейса |

`ArcanaBonus` — объединение basic `{ attribute_name, attribute_bonus, upgrade_bonus }` и unique `{ bonus_description, bonus_value, upgrade_bonus }`, различаемое по `bonus_type`. `ArcanaInstance` хранит `arcanaId`, `level`, необязательные `selectedAbilityId` и `randomTargetSlot`. Структуры перечислены в `src/types`; не исправлять орфографию ключей вроде `attack_spead` без миграции всех потребителей.

Изображения подключаются через `assetUrl`, `characterAsset`, `arcanaImagePath`, `locationAssetPath` и специализированные адаптеры. Существуют намеренные исключения имён: двойное `.png.png`, `Wizard_backgound.png`, `Midnight_Prism.png.png`, три cross-folder пути навыков противников. Их покрывают тесты. Каталоги вычисляются не по порядку файлов. Графику не удалять по одному текстовому поиску: пути часто строятся динамически. `EquipmentImage` показывает fallback при ошибке; `CrossfadeImage` оставляет предыдущий кадр до загрузки нового.

## CSS и анимации

Обновление 29 октября 2026: `hero-effects` переносит иконки и растёт по содержимому без ограничения max-height и внутренней прокрутки. Способности врагов и боссов используют общую rich-карточку навыка без звёзд уровня; урон, радиус и длительность скрыты при нуле или отсутствии значения. Перезарядка отображается, если задана. Эффекты локаций остаются обычными подсказками.

Порядок: `index.css` в main; в App — `heroes.css`, `tooltips.css`, `equipment.css`, `enemies.css`, `arcana.css`, `transitions.css`.

| Файл | Владелец стилей |
|---|---|
| `index.css` | Reset, шрифт, focus, `[hidden]`, общие переменные цветов |
| `heroes.css` | Общая сцена, навигация, селектор, дуги, панель, статистика, hero-effects, crossfade |
| `tooltips.css` | Общая всплывающая подсказка, rich-карточка навыка, числовые состояния, tooltip-image и оболочка эффекта предмета/Аркана |
| `equipment.css` | Каталог, граф предметов, слоты и их звёзды, карточка предмета и содержимое эффекта |
| `enemies.css` | Селектор локаций, карусель, режимы врага, адаптация общей панели |
| `arcana.css` | Категории и раскрытие, карты, связи SVG, детали, колонка способностей и локальное сравнение |
| `transitions.css` | Межстраничная координация scene-menu, размещение общих областей на мобильных экранах, общий reduced-motion |

Общие цвета: `--color-number` (#8a9bc3), `--color-bonus-positive` (#59d453). Другие переменные динамические: `--arcana-color`, `--rarity`, `--rows`, `--catalog-row-height`, `--level-color`, `--star-image`, `--slide-direction`. Inline-стили обоснованы для этих данных, SVG-координат, позиционирования portal и цвета текущей локации.

Используются cqw (контейнер страницы), svh, rem и процентные ограничения; не заменять их на vw без проверки широких окон. Основной мобильный breakpoint — ширина 900px либо соотношение сторон 6/5; дополнительно 600px и 500px. Локальные адаптации общей карточки на странице Таро остаются в arcana.css.

Состояния задаются классами, `aria-*` и `data-*`: selected/expanded, drop, active, fading. `scene-menu` постоянно смонтирован для анимации выхода; закрытые меню inert. Категория раскрывается через grid `0fr → 1fr`, opacity и visibility. Общий reduced-motion отключает анимации с `!important`; это намеренная гарантия доступности. `!important` для мобильной позиции навыков врага переопределяет их вычисленные inline left/top; `[hidden]` защищает скрытую сцену от display-правил.

**Все стили одного компонента должны находиться в одном логическом месте. Не допускается бессистемное добавление повторных селекторов в конец CSS-файлов.** Состояния располагать у базового правила, адаптивные правила — в последовательных media-блоках файла владельца. Общие анимации и композиция scene-menu — осознанное исключение. Не объединять похожие цвета/размеры, если они намеренно различаются.

## Проверки и дальнейшая разработка

`npm test`: редьюсеры, восстановление, уровни и формулы, лимиты, назначение способностей, случайные слоты, направленные связи, форматирование, пути реальных изображений. `npm run test:render`: SSR всех страниц и важных состояний Таро; не проверяет мышь, browser layout, ResizeObserver, CSS-переходы или localStorage реального браузера.

Перед изменением искать существующий компонент, функцию и CSS-владельца. Не дублировать бизнес-логику в UI, не вводить новое хранилище бонусов. Проверять динамические пути и импорты перед удалением. После замены убирать подтверждённо устаревший код. Сохранять публичные props и имена файлов без необходимости. Обновлять этот документ при изменении архитектуры, сохранений, формул, структуры CSS или команд проверки.

Для визуального приёмочного теста открыть все четыре режима в широком и узком окне; проверить переходы и категории, наведение/закрепление tooltip, варианты навыков, drop/отмену/снятие, случайную цель, смену локации/босса, reload сборки и reduced-motion. На дату аудита браузерный host недоступен; полное визуальное соответствие не подтверждено. Не маскировать этот пробел формулировкой «все визуальные тесты прошли».
